# Запуск Джарвиса и перенос на сервер

## Локальный запуск

Из корня, после сборки фронтенда и установки `.[jarvis]`:

```bash
.venv/bin/python scripts/jarvis_stack.py --runs-dir out/jarvis-evidence-20260926/runs --check
.venv/bin/python scripts/jarvis_stack.py --runs-dir out/jarvis-evidence-20260926/runs
```

Интерфейс — http://127.0.0.1:5199. Один процесс запускает API и web-прокси,
ожидает health и завершает оба сервиса при остановке. Порт API — 8010.
Флаг `--check` проверяет конфигурацию и наличие данных; генерация проверяется настоящим вопросом.
При занятых портах можно задать `--web-port` и `--api-port`.
`--runs-dir` переопределяет контейнерный путь /out из существующего env-файла;
на сервере путь берётся из серверного env-файла. `--check` завершается ошибкой,
если каталог записанных прогонов недоступен.

`.env.local` содержит серверный ключ NunAway. Для новых поисковых расчётов дополнительно
задаются `AIOS_DATA_ROOT` (production surrogate) и `AIOS_DOCS_ROOT` (Model_Z и нормативы).
Они должны указывать на реальные каталоги, а не контейнерные `/app` или `/out`.

## Состав переносимого пакета

```bash
.venv/bin/python scripts/package_jarvis.py out/releases/jarvis-release.tar.gz
```

Архив содержит собранный интерфейс, код, конфигурацию без секретов, документы,
JSON-витрину, пакет финального кандидата и два записанных прогона с журналом/откликом.
Рядом создаётся manifest SHA-256 всех файлов и архива. Сессии, ключ, окружение Python,
большие двоичные выходы OPM и runtime суррогата в архив не входят.
Скрипт отказывается перезаписывать существующий архив.

## Сервер Linux

Целевой каталог — `/opt/aios`; пользователь сервиса — `aios`. Перед запуском нужны:

1. Распакованный релиз в `/opt/aios` и Python 3.11+.
2. Виртуальное окружение `/opt/aios/.venv` с установленным `.[jarvis]`.
3. `/etc/aios/jarvis.env`, созданный из `deploy/jarvis.env.example`, с ключом,
   владельцем `aios` и правами `600`.
4. Доступный для записи `/opt/aios/out`. Права на код и ключ ограничиваются пользователем сервиса.
5. Для новых вычислений: ML-зависимости из `requirements-ml.txt`, полный runtime в
   `/opt/aios-runtime/data`, документы в `/opt/aios-runtime/docs`.
6. Для альтернативного OPM-прогона: установленный Docker CLI и доступ пользователя
   сервиса к заранее настроенному Docker daemon с образом OPM. Сам архив такие права
   не выдаёт. При отсутствии вычислительного окружения остаются доступными объяснения
   сохранённых результатов; запуск нового расчёта не следует считать проверенным.

```bash
cd /opt/aios
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[jarvis]'
.venv/bin/python scripts/jarvis_stack.py --env-file /etc/aios/jarvis.env --check
```

Файл `deploy/aios-jarvis.service` устанавливается в systemd после подготовки пользователя
и окружения. Он запускает оба процесса, перезапускает их после сбоя и останавливает
дочерние процессы при остановке службы. Логи — `journalctl -u aios-jarvis`.
Оба внутренних порта слушают только loopback.

## HTTPS и доступ

`deploy/nginx-jarvis.conf.example` — шаблон reverse proxy. Перед установкой указать
реальный домен, действующий сертификат и файл паролей `/etc/nginx/aios.htpasswd`.
SSE-буферизация отключена, таймаут потока — 120 секунд. API и UI имеют один origin;
ключ LLM остаётся только на сервере. Наличие шаблона не означает, что DNS/TLS настроены:
эта часть принимается на конкретном адресе сервера.

## Приёмка после переноса

- Health через внешний HTTPS, затем настоящий вопрос и карточка с run/well/date.
- Объяснение 62/0 для диагностического прогона; переход на график и возврат.
- Отказ объяснить отсутствующий журнал final candidate и явный статус отклонённого плана.
- Скачивание заключения; перезагрузка страницы и восстановление истории.
- Отмена ответа и следующий вопрос; повтор после временного отказа upstream.
- Озвучка и русский микрофон в браузере выступающего.
- Перезапуск systemd без потери сессий и записанных прогонов.

План `jarvis-policy-20260926` — диагностический, `sound=false`; это явная часть показа.
У `candidate-018` нет исходного журнала генерации. Новый поиск может завершиться без
допустимого варианта в заданном бюджете; интерфейс показывает причины, а не обещает успех.
