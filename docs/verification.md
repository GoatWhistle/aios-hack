# Проверка

> Что именно проверяется, чем, и что каждая проверка ловит. Сильнейшее звено — холодный
> повтор из чистого клона, воспроизведший ЧДД до последнего разряда. Рядом с ним — круговая
> проверка пакета сдачи, отказывающаяся собирать пакет при расхождении заявленного и
> пересчитанного, и архитектурные сторожа с пустыми списками исключений.

**Читайте это, если хотите воспроизвести результат или понять, что удерживает правила** ·
**Рядом:** [доказательства](evidence.md) · [границы](limitations.md) ·
[архитектура](architecture.md)

## Цепочка статусов

Прогон идёт строго по цепочке и не умеет её сократить:

```text
searched  →  verified   →  ready_to_submit
              ↘ rejected (если sound = false)
```

`searched` ставит поиск на суррогате. `verified` или `rejected` ставит проверка настоящим
OPM. `ready_to_submit` ставит **только** `aios run submit`, и только после того, как пакет
собран и его круговая проверка сошлась. Статус обещает существующий пакет, а не просто
корректный прогон — реализация в
[`workflow.py`](../backend/contexts/runs/application/workflow.py).

Пакет не соберётся, если прогон не верифицирован или если в экономике нет ЧДД от OPM.
Прогноз суррогата в заявляемую величину не подставляется ни при каких условиях.

## Холодный повтор

Самая сильная проверка проекта: заново посчитать сохранённое расписание из чистого клона
и сравнить результат с записанным.

```bash
bash scripts/cold_repeat.sh --run-id <id>
```

Результат для `candidate-005` лежит в
[`artifacts/final-readiness-20260909/cold-repeat/candidate-005/economics/result.json`](../artifacts/final-readiness-20260909/cold-repeat/candidate-005/economics/result.json):

```text
measured_npv      = 1464123030.4381707
npv_methodology   = 1464123030.4381707
sound             = true
source_run_id     = 20260909T201028-4ef81589f96f
```

Два числа сошлись до последнего разряда: ЧДД, измеренный на отклике симулятора, и ЧДД,
посчитанный по эталонной методике организаторов. Хеши конфигурации экономики и версии
методики совпадают с записанными у этого кандидата в
[`evaluations.json`](../artifacts/final-readiness-20260909/evaluations.json).

Рядом с `artifacts/final-readiness-20260909/cold-repeat/candidate-005/economics/result.json` в том же каталоге лежат `manifest.json`,
`artifacts/final-readiness-20260909/cold-repeat/candidate-005/validation/result.json` и `artifacts/final-readiness-20260909/cold-repeat/candidate-005/validation/constraints_report.json` — то есть повтор
прошёл не только экономику, но и проверку ограничений.

## Круговая проверка пакета сдачи

```bash
aios run submit  --run-id <id>
aios selfcheck --submission out/runs/<id>/submission
```

Пакет содержит `well_schedule.inc` и `claimed_npv.json` с заявленным ЧДД и хешами
расписания, отклика, дека, ограничений и методики. `selfcheck --submission` пересчитывает
хеши лежащих в каталоге файлов и сверяет их с заявленными — проверка того же рода, какую
сделает организатор.

Смысл в том, что заявление и предмет заявления нельзя разъединить: подменив расписание,
получаешь несовпадение хеша; подменив число, получаешь несовпадение с пересчётом.

## Что означает `sound = true`

Больше, чем успешное завершение Flow. Сходимость симулятора и допуск — разные вещи, и
система их различает. Показательный отрицательный пример: диагностический прогон
`jarvis-policy-20260926` получил OPM `OK` и при этом `sound=false` — 165 блокирующих
нарушений водного баланса при 785 замечаниях всего.

Из 89 оценённых кандидатов кампании 09.09 `sound=true` получили пять. Допуск —
редкое событие.

## Проверки предсказания

Семь физических инвариантов применяются и к выходу суррогата, а не только к результату
симулятора: неотрицательность, обводнённость в [0, 1], монотонность накопленных объёмов,
нулевые расходы у закрытой скважины, пределы BHP, отклик на закачку и материальный баланс.
Подробности и строгости — в [surrogate.md](surrogate.md#физические-проверки).

Отдельно стоит отметить поведение при невозможности проверить: дифференциальные инварианты
требуют, чтобы пара расписаний различалась только закачкой, и при невыполнении условия
возвращают статус `skipped` с причиной. Проверка BHP так же честно сообщает, что не
выполнялась, если дек не объявил числовых пределов. Пропуск никогда не маскируется
под успех.

## Целостность артефактов

Каждый файл весов самопроверяется при загрузке по отпечатку содержимого — хешируются и
метаданные, и сырые байты тензоров. Несовпадение даёт явную ошибку, а не тихо неверный
прогноз. Блочная голова ЧДД дополнительно закрепляет SHA-256 собственного исходного файла
`kernel.py`: изменив формулу ядра без переобучения, веса загрузить не удастся.

Манифест сверяет SHA-256 сценарного OOD-артефакта и контекста признаков, а `verify_bundle`
проверяет каждый файл против `release.json` и отклоняет записи инвентаря, выходящие за
корень пакета.

## Архитектурные сторожа

Правила слоёв — не договорённость, а падающие тесты. Каталог
[`tests/architecture/`](../tests/architecture).

| Проверка | Что ловит |
|---|---|
| [`tests/architecture/backend/test_context_boundaries.py`](../tests/architecture/backend/test_context_boundaries.py) | `domain` импортирует `application` или `infrastructure`; приватные символы ходят между контекстами. **Списки исключений пусты** |
| `tests/architecture/backend/test_no_env_outside_settings.py` | `os.environ` или `getenv` появились вне `backend/shared/settings.py` |
| `tests/architecture/backend/test_no_test_code_in_production.py` | Тестовый код просочился в production-модули |
| [`test_layers.py`](../tests/architecture/test_layers.py) | Вернулись удалённые пакеты `backend/core`, `backend/ml` и другие legacy-слои |
| [`test_markdown_links.py`](../tests/architecture/test_markdown_links.py) | Путь в обратных кавычках в любом отслеживаемом `.md` не существует на диске |
| `frontend/` | Паритет i18n, знаний, notice и токенов темы |

Последний сторож стоит отдельного слова: он означает, что документация не может тихо
устареть в части путей. Путь, которого на машине нет, пишется без обратных кавычек —
и это осознанное решение, а не обход проверки.

## Золотые снимки

`tests/golden/` фиксирует поведение до рефакторинга; правило сверки для каждого файла
описано в `tests/golden/MANIFEST.json`.

| Файл | Что удерживает |
|---|---|
| `showcase.json` | sha256 каждого из 1284 JSON витрины, байт в байт, кроме полей `notice` |
| `behaviour.json` | ЧДД, пакет чемпиона, сценарии, сетка, статистика таймлайна |
| `api_surface.json` | Публичные символы 226 модулей: ни один не исчезает молча |
| `errors.json` | Имена всех 80 классов ошибок |
| `cli.json` | Коды выхода и сообщения показательных вызовов CLI |

**Чего снимки не гарантируют.** Это проверка неизменности, а не правильности. Они ловят
регресс рефакторинга — «было одно, стало другое», — но молчат, если поведение было
неверным до снятия снимка.

## Как воспроизвести

```bash
python3 -m venv .venv
.venv/bin/pip install -e '.[dev,ml]'
aios selfcheck                       # что доступно на этой машине
pytest -q                            # тесты; требующие данных и Docker помечаются skip
```

Для полной цепочки нужны данные организаторов (`AIOS_DOCS_ROOT`), Docker с образом OPM
и веса суррогата. Что именно из этого есть, печатает `aios selfcheck`; порядок установки —
в [running.md](running.md).
