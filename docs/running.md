# Запуск

> Свежий клон **неполон по замыслу**: ни веса, ни датасеты, ни выгрузки прогонов, ни данные
> организаторов в git не хранятся. Зато JSON-витрина лежит в репозитории, поэтому консоль и
> Джарвис работают без единого прогона OPM. Команды делятся на три группы по тому, что им
> дополнительно нужно; что есть на конкретной машине, печатает `aios selfcheck`.

**Читайте это, если запускаете систему или переносите её на сервер** · **Рядом:**
[Джарвис](jarvis.md) · [проверка](verification.md) · [архитектура](architecture.md)

---

## Установка

```bash
python3 -m venv .venv
.venv/bin/pip install -e '.[dev,ml]'
aios selfcheck
```

`aios selfcheck` печатает, что нашлось: каталог данных организаторов, дек
`Model_Z_sch.inc`, эталонный расчётчик, нормативы, собранный фронт, доступность Docker,
наличие `numpy` и `torch`. По её выводу сразу видно, какие команды ниже запустятся.

Интерфейс:

```bash
cd frontend
npm ci
npm run build
```

> **Windows.** Вывод русскоязычный, а консоль по умолчанию в cp1252 — команды падают с
> `UnicodeEncodeError` до того, как что-то напечатают. Ставьте `PYTHONIOENCODING=utf-8`
> перед вызовом. Интерпретатор здесь — `.venv/Scripts/python.exe`, не `.venv/bin/python`.

## Три группы команд

### Работает сразу после установки

| Команда | Что даёт |
|---|---|
| `pytest -q` | Весь набор тестов; требующие данных и Docker помечаются skip, а не падают |
| `aios selfcheck` | Состояние окружения |
| `aios selfcheck --submission <каталог>` | Сверка готового пакета сдачи с заявленными хешами |
| `aios web` | Консоль на готовой витрине, `http://localhost:8000` |
| `aios jarvis` | Сервис ассистента; для ответов модели нужен ключ |

### Требует данных организаторов

Каталог задаётся переменной `AIOS_DOCS_ROOT`; без неё автопоиск смотрит в `../docs` и
`../docs-src` рядом с репозиторием.

| Команда | Что даёт |
|---|---|
| `aios npv` | Расчёт ЧДД по методике и сверка с эталонным расчётчиком |
| `aios emit` | Эмит `well_schedule.inc` из дека |
| `aios run verify --run-id <id>` | Верификация расписания настоящим OPM (нужен ещё Docker) |
| `aios run submit --run-id <id>` | Сборка пакета сдачи из верифицированного прогона |
| `scripts/cold_repeat.sh --run-id <id>` | Холодный повтор из чистого клона |

### Требует ещё и весов суррогата

| Команда | Что нужно дополнительно |
|---|---|
| `aios run search --run-id <id>` | Веса, отклик базового прогона, матрица λ |
| `aios run compare --run-id <id>` | Веса: по ним строится оценщик отбора |
| `aios surrogate-check` | Веса |

Веса разрешаются в
[`artifacts.py`](../backend/contexts/optimization/infrastructure/artifacts.py): по умолчанию
берётся указатель [`data/surrogate-production.json`](../data/surrogate-production.json)
либо каталог `data/model-production/`. Установка опубликованного пакета:

```bash
python3 scripts/install_surrogate_runtime.py
```

## Основная цепочка

```bash
aios run search  --run-id <id>
aios run verify  --run-id <id>
aios run submit  --run-id <id>
aios selfcheck --submission out/runs/<id>/submission
```

Статусы идут строго `searched` → `verified` (либо `rejected`) → `ready_to_submit`.
Последний ставит **только** `submit`, и только после того, как пакет собран и его круговая
проверка сошлась. Подробнее — в [verification.md](verification.md).

Каждый прогон изолирован в `out/runs/<run-id>/`: `manifest.json`, `schedule/`,
`prediction/`, `opm/`, `validation/`, `economics/`, `inputs/`, `ui/`.

## Переменные окружения

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `AIOS_DOCS_ROOT` | автопоиск `../docs`, `../docs-src` | Каталог данных организаторов |
| `AIOS_PROJECT_ROOT` | каталог с `pyproject.toml` | Корень репозитория |
| `AIOS_DATA_ROOT` | `data/` | Входы OPM, кэш и артефакты |
| `AIOS_OUT_DIR` | `out/` | Результаты |
| `AIOS_CONSTRAINTS_PATH` | [`config/competition-constraints.json`](../config/competition-constraints.json) | Файл кейса |
| `AIOS_OOD_THRESHOLD` | `0.0` | Порог отсечения по области применимости |
| `AIOS_OPM_BUDGET_JOURNAL` | `<AIOS_OUT_DIR>/opm-budget.jsonl` | Журнал прогонов Flow |
| `AIOS_RUN_INITIATOR` | по среде | Кто запустил: `cli`, `ui`, `test` |
| `AIOS_SURROGATE_MANIFEST` | `data/surrogate-production.json` | Указатель на веса |
| `AIOS_SURROGATE_BUNDLE` | — | Каталог весов вместо указателя |
| `AIOS_HOST` / `AIOS_PORT` | `0.0.0.0` / `8000` | Адрес консоли |
| `AIOS_UI_DATA` | витрина в репозитории | Каталог JSON-витрины |

Переменные ассистента — в [jarvis.md](jarvis.md#настройка). Единственное место, где
читается окружение, — `backend/shared/settings.py`, и это удерживается тестом.

## Джарвис

Локально, двумя процессами или одним лаунчером:

```bash
.venv/bin/python scripts/jarvis_stack.py --runs-dir out/<каталог>/runs --check
.venv/bin/python scripts/jarvis_stack.py --runs-dir out/<каталог>/runs
```

Один процесс поднимает API и веб-прокси, ждёт health и завершает оба сервиса при
остановке. Порт API — 8010, интерфейс — на веб-порту. Флаг `--check` проверяет
конфигурацию и наличие данных и завершается ошибкой, если каталог записанных прогонов
недоступен; генерацию он **не** проверяет — для этого нужен настоящий вопрос.
При занятых портах есть `--web-port` и `--api-port`.

Конфигурация провайдера берётся из `.env.local` (пример без секрета — в `.env.example`);
экспортированные в терминале переменные имеют приоритет, другой файл задаётся через
`--env-file`.

## Docker

```bash
docker compose --env-file .env.local up --build jarvis web
```

Сервис `web` проксирует `/api/jarvis/*` на `jarvis:8010`, поэтому фронт в контейнере ходит
на тот же origin; адрес апстрима меняется через `AIOS_JARVIS_UPSTREAM`. Данные
организаторов в образ не входят — монтируются томом. Для новых расчётов `web` нужен полный
каталог runtime-данных с весами и Model_Z.

Пути внутри контейнера задаются отдельно от локальных: в compose корни документов —
`AIOS_JARVIS_DOCS=/app;/data/docs`, внешний архив монтируется read-only в `/data/docs`,
сессии — в `/out/jarvis/sessions`. Опубликованный host-порт Jarvis по умолчанию привязан
к `127.0.0.1` (`AIOS_JARVIS_BIND_ADDRESS`).

## Перенос на сервер

Собрать переносимый пакет:

```bash
.venv/bin/python scripts/package_jarvis.py out/releases/jarvis-release.tar.gz
```

Архив содержит собранный интерфейс, код, конфигурацию **без секретов**, документы,
JSON-витрину, пакет финального кандидата и записанные прогоны с журналом и откликом.
Рядом создаётся manifest SHA-256 всех файлов и архива. Сессии, ключ, окружение Python,
большие двоичные выходы OPM и runtime суррогата в архив не входят. Скрипт отказывается
перезаписывать существующий архив.

Целевой каталог — `/opt/aios`, пользователь сервиса — `aios`. Перед запуском нужны:

1. Распакованный релиз в `/opt/aios` и Python 3.11+ (проверено на 3.12).
2. Виртуальное окружение `/opt/aios/.venv` с установленным `.[jarvis]`.
3. `/etc/aios/jarvis.env` из `deploy/jarvis.env.example`, с ключом, владельцем `aios`
   и правами `600`.
4. Доступный для записи `/opt/aios/out`.
5. Для новых вычислений: ML-зависимости, полный runtime в `/opt/aios-runtime/data`,
   документы в `/opt/aios-runtime/docs`.
6. Для прогонов OPM: установленный Docker CLI и доступ пользователя сервиса к daemon с
   образом OPM. **Сам архив таких прав не выдаёт.** Без вычислительного окружения
   остаются доступными объяснения сохранённых результатов, а запуск нового расчёта
   проверенным считать нельзя.

```bash
cd /opt/aios
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[jarvis]'
.venv/bin/python scripts/jarvis_stack.py --env-file /etc/aios/jarvis.env --check
```

Файл `deploy/aios-jarvis.service` устанавливается в systemd после подготовки пользователя
и окружения: он запускает оба процесса, перезапускает их после сбоя и останавливает
дочерние при остановке службы. Логи — `journalctl -u aios-jarvis`. Оба внутренних порта
слушают только loopback.

### HTTPS и доступ

`deploy/nginx-jarvis.conf.example` — шаблон reverse proxy. Перед установкой указать
реальный домен, действующий сертификат и файл паролей `/etc/nginx/aios.htpasswd`.
SSE-буферизация отключена, таймаут потока — 120 секунд. API и UI имеют один origin,
ключ модели остаётся только на сервере.

**Наличие шаблона не означает, что DNS и TLS настроены.** CORS ограничивает браузерные
источники, но не является аутентификацией. Если меняете привязку на публичный интерфейс,
настройте внешний контроль доступа и TLS **до** запуска.

### Приёмка после переноса

- Health через внешний HTTPS, затем настоящий вопрос и карточка с прогоном, скважиной и датой.
- Объяснение конкретной пары «скважина — шаг» для диагностического прогона.
- Отказ объяснить отсутствующий журнал и явный статус отклонённого плана.
- Скачивание заключения; перезагрузка страницы и восстановление истории.
- Отмена ответа и следующий вопрос; повтор после временного отказа провайдера.
- Озвучка и русский микрофон в браузере выступающего.
- Перезапуск systemd без потери сессий и записанных прогонов.

## Типовые отказы

| Симптом | Причина |
|---|---|
| `UnicodeEncodeError` до любого вывода | Консоль Windows в cp1252; поставьте `PYTHONIOENCODING=utf-8` |
| Job создаётся, worker падает на отсутствующем артефакте | `AIOS_DATA_ROOT` или `AIOS_DOCS_ROOT` указывают на контейнерные пути вместо реальных |
| `503 no-api-key` | Ключ модели не задан; консоль при этом работает |
| `HTTP 402` от провайдера | Баланс внешнего шлюза исчерпан |
| Поиск отклонил всех кандидатов | Ожидаемый исход при консервативном пороге OOD; см. [границы](limitations.md) |
