# Джарвис

> Визуальный ассистент консоли: вопрос словами превращается в сцену из карточек, собранных
> из той же JSON-витрины, которую читает фронт. Карточка несёт данные, происхождение и
> возможное действие, открывающее нужный экран. Джарвис объясняет план и результаты —
> он не управляет скважинами и не вычисляет заявляемый ЧДД. Его главное свойство не в том,
> что он отвечает, а в том, что он отказывается отвечать, когда оснований нет.

**Читайте это, если хотите понять, чему в ответах ассистента можно верить** ·
**Рядом:** [для жюри](for-judges.md) · [границы](limitations.md) ·
[архитектура](architecture.md)

---

## Путь вопроса

```text
Консоль → JarvisProvider → POST /api/jarvis/ask → Оркестратор
  → модель вызывает предметные инструменты → карточки + данные
  → модель составляет подпись и ответ → сторож чисел
  → SSE-события → сцена, карточки, история
```

Фронт формирует контекст из активного сценария, шага, даты, выбранной скважины и маршрута,
и передаёт его вместе с вопросом. Оркестратор
([`orchestrator.py`](../backend/contexts/assistant/application/orchestrator.py)) собирает
системный промпт с этим контекстом, ведёт до пяти раундов вызова инструментов, хранит
память сессии и передаёт события в поток.

Поток несёт `scene`, `status`, `card`, `caption_delta`, `caption`, `answer_delta`,
`answer`, `warning`, `suggestions`, `done`, `error`. Промежуточные `*_delta` показываются
до окончательной проверки — это важно помнить на живом показе.

## Инструменты

**27 предметных инструментов**, реестр — в
[`backend/contexts/assistant/application/tools/__init__.py`](../backend/contexts/assistant/application/tools/__init__.py), схемы
и валидация аргументов — в
[`backend/contexts/assistant/application/tools/registry.py`](../backend/contexts/assistant/application/tools/registry.py).
Темы: скважина и её ряды, сравнение двух скважин, метрики поля, события, решения и правила,
λ, сравнение сценариев и прогонов, ЧДД и сдача, ограничения, физический отчёт,
документация, карта системы, подготовка нового кейса.

Каждый инструмент читает витрину, каталог прогонов, базу знаний или индекс документов через
порты. Аргументы вне схемы отклоняются **до** вызова обработчика: `rank_wells.limit`
ограничен диапазоном 1–10, `well_series.control_step` — 0–224.

### Отказ как проектное решение

Это та часть, которую стоит проверять на защите. Для каждого инструмента описано, что он
делает при недостатке данных, и ни в одном случае это не выдумывание:

| Ситуация | Поведение |
|---|---|
| Нет записи для пары «скважина — шаг» | Типизированный отказ без реконструкции причины |
| Нет журнала генерации прогона | Отказ с указанием отсутствия записи |
| Правило без измеренного вклада | Результат явно помечается «не измерено» |
| Термин не найден в индексе | Помечается как общее объяснение, не как цитата |
| Нет событий за интервал | Пустой список, а не выдуманное событие |
| Нет physics-отчёта | Типизированный отказ, а не допуск по умолчанию |
| Нет пакета сдачи | Карточка явного отсутствия; неполный пакет не объявляется валидным |
| Маршрут не документирован | Действие у карточки не строится |

Отсутствующее поле остаётся пустым и **не превращается в ноль** — это отдельно
оговорённое правило.

## Сторож чисел

Окончательный текст проходит фильтр
([`guard.py`](../backend/contexts/assistant/domain/guard.py) и
[`caption.py`](../backend/contexts/assistant/application/caption.py)): число, не
опирающееся на данные карточек или артефактов этого ответа, из текста удаляется. Блоки
кода без подтверждённого источника отсекаются так же. Для подписи возможна одна попытка
переписать её.

Две честные оговорки. Это ограничение на **текстовый ответ**, а не проверка физики или
правильности расчёта. И потоковые дельты появляются раньше фильтрации, так что на экране
на мгновение может оказаться непроверенный текст.

Отдельно закреплено правило для статуса допуска: положительный вердикт в тексте разрешён
только при записанном `accepted_for_recorded_checks`, отрицательный — только при
`rejected`. Значение `unknown`, единственный `sound=true`, отсутствие проверки или
смешанные вердикты не подтверждают ни того, ни другого.

## Карточки и навигация

У каждой карточки есть `type`, `title`, `payload`, `provenance` и возможное `action`.
Действие применяется в порядке сценарий → маршрут → шаг → скважина → воспроизведение →
подсветка: это навигация и фокус интерфейса, а не изменение расчёта.

Фронт ограничивает сцену восемью карточками. Единицы измерения и даты проходят через общий
локализованный форматтер; в API и payload остаются исходные теги единиц и ISO-даты.

## Голос и сессии

Ввод — браузерный `SpeechRecognition`; при его недоступности возможна серверная
расшифровка, требующая отдельного `OPENROUTER_API_KEY`. Вывод — `edge-tts` без отдельного
ключа, с запасным браузерным `speechSynthesis`.

Сессии сохраняются в `AIOS_JARVIS_SESSIONS` в JSONL-файлах: там есть вопросы, карточки и
ответы, поэтому **каталог доступен только доверенным пользователям машины**. После 30 дней
бездействия каталог сессии удаляется; срок задаётся `AIOS_JARVIS_SESSION_TTL_DAYS`
в диапазоне от 1 до 3650 дней.

## Зависимость от внешнего шлюза

Джарвису нужен внешний LLM-провайдер, и это его самая жёсткая зависимость.

| Состояние | Что происходит |
|---|---|
| Ключа нет | `/api/jarvis/health` и `/ask` отвечают `503` с телом `{"ok": false, "error": "no-api-key"}` и именем нужной переменной |
| Баланс исчерпан | Провайдер отдаёт `HTTP 402`; интерфейс показывает «Провайдер модели отклонил запрос» и кнопку повтора |
| Провайдер молчит | Каждый поток имеет собственный бюджет 60 секунд; при наличии одного записанного журнала выдаётся фактический разбор с явным предупреждением |

Консоль при этом продолжает работать полностью — расчётная часть от ассистента не зависит.
**Автоматического воспроизведения фикстур в продукте нет**: файлы
`frontend/public/jarvis/fixtures/` существуют для записи и проверок, а production-сборка
их удаляет. Заготовленный текст никогда не выдаётся за живой ответ модели.

## Измеренная скорость

Серия из 20 последовательных запросов через веб-прокси:

| Величина | Значение |
|---|---|
| Завершились `done` без ошибки | 20 из 20 |
| Вернули карточку | 19 из 20 |
| Первая карточка, медиана / P95 | 4,43 с / 9,76 с |
| Полный ответ, медиана / P95 / максимум | 12,50 с / 33,36 с / 44,38 с |

Это серия на одной локальной машине при одном состоянии шлюза. Она не измеряет отрисовку
в браузере и ничего не гарантирует при другом балансе ключа: в сессии, когда снимались
иллюстрации к этой документации, тот же шлюз отвечал `HTTP 402`.

## Настройка

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `JARVIS_PROVIDER` | `openrouter` | `openrouter`, `anthropic` или `openai-compatible` |
| `JARVIS_API_KEY` | — | Ключ совместимого шлюза |
| `JARVIS_BASE_URL` | — | Обязателен для `openai-compatible` |
| `JARVIS_MODEL` | зависит от провайдера | Для `openai-compatible` обязателен |
| `JARVIS_MAX_TOKENS` | `2400` | Потолок ответа модели |
| `JARVIS_MAX_CONCURRENT_REQUESTS` | `8` (от 1 до 64) | Предел одновременных запросов |
| `AIOS_JARVIS_KNOWLEDGE` | `frontend/public/jarvis/knowledge` | База знаний |
| `AIOS_JARVIS_DOCS` | — | Корни Markdown через `;` |
| `AIOS_JARVIS_RUNS` | — | Каталог импортированных прогонов |
| `AIOS_JARVIS_SESSIONS` | — | Каталог сессий |
| `AIOS_JARVIS_HOST` / `AIOS_JARVIS_PORT` | `127.0.0.1` / `8010` | Адрес процесса |

Секрет остаётся на сервере; переменные `VITE_*` для него не используются. В режиме
`openai-compatible` ключ уходит только на настроенный URL. TLS проверяется по системным
сертификатам с добавлением `certifi`.

Диагностические записи с идентификатором запроса, моделью, длительностью, исходом и кодом
ошибки идут в stdout сервиса. **Ключи и текст вопросов в них не записываются.**

Запуск, перенос на сервер и доступ — в [running.md](running.md#джарвис).
