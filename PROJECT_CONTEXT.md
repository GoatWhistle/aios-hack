# Контекст AIOS для защиты

Снимок: 26.09.2026, репозиторий `aios-hackv2`, коммит `d0da1c3`. Команда прошла в финал. Вычислительное решение сохраняем; фронтенд и Джарвиса можно дорабатывать, а конфигурацию деплоя менять по необходимости. Этот файл служит картой системы и опорой для ответов на защите.

## Задача и главный тезис

Трек 2: управление фондом Model_Z (103 скважины) на горизонте с 01.01.2007, 224 интервала управления. Подбираем команды добычи и закачки, соблюдаем ограничения кейса, максимизируем ЧДД. На выходе — `well_schedule.inc` и заявленный ЧДД. Исходная постановка и ограничения: исторические [TASK.md](../aios-hack/docs/TASK.md), актуальные [horizon-model-z.json](config/horizon-model-z.json) и [competition-constraints.json](config/competition-constraints.json).

Защитная формулировка: **численные политики и поиск предлагают управление; суррогат быстро оценивает кандидатов; итоговый план подтверждается OPM Flow; заявляемый ЧДД считается по отклику OPM и методике организаторов на том же расписании.** Суррогат не подменяет итоговую гидродинамическую проверку. Реализация цепочки: [search_use_case.py](backend/contexts/optimization/application/search_use_case.py), [verification_run.py](backend/contexts/optimization/application/verification_run.py), [workflow.py](backend/contexts/runs/application/workflow.py).

## Как устроена система

1. **Кейс и модель.** JSON кейса задаёт годовые лимиты, простои, водный баланс, BHP и диагностику компенсации. Источник каждого важного параметра помечен как `organizer`, `assumption` или `diagnostic`; коридор компенсации 0.85–1.15 в базовом кейсе диагностический, а не обязательное условие организаторов. См. [config/README.md](config/README.md) и [constraints](backend/contexts/constraints/).
2. **Связность и политика.** Влияние закачки измеряется как λ; политика распределяет решения по уровням поле → группа → скважина, использует правила R0–R7 и пишет след решений. Это численные агенты, не отдельные LLM на скважинах. См. [connectivity](backend/contexts/connectivity/), [policy](backend/contexts/policy/).
3. **Поиск.** Оптимизатор строит расписания, фильтрует статические нарушения, OOD, физические флаги, допуск BHP и бюджет OPM. Есть основной поиск и резервные стратегии около базового плана. См. [optimization](backend/contexts/optimization/), особенно [search_use_case.py](backend/contexts/optimization/application/search_use_case.py).
4. **Суррогат.** Рабочий пакет содержит ансамбль трёх траекторных сетей, прямую голову ЧДД и сценарный OOD. Прогноз ЧДД смешивает прямую оценку (80%) и экономику прогнозной траектории (20%). Модель обучалась на откликах OPM; текущие веса и их хеши заданы [surrogate-production.json](data/surrogate-production.json) и [release.json](data/release.json). Историческое подробное описание — [SURROGATE_DEFENSE.md](../aios-hack/aios/SURROGATE_DEFENSE.md). Текущие модули — [surrogate](backend/contexts/surrogate/).
5. **Верификация и экономика.** Для выбранного расписания собирается дек, запускается OPM, проверяются динамические ограничения и согласованность артефактов, затем считается ЧДД по нормативам. `sound=true` требует больше, чем успешное завершение Flow. См. [submission.py](backend/contexts/simulation/application/submission.py), [economics](backend/contexts/economics/).
6. **Жизненный цикл.** `searched` → `verified` либо `rejected` → `ready_to_submit`. `submit` разрешён только для `sound=true` и числового OPM ЧДД; пакет содержит расписание, `claimed_npv.json` и хеши провенанса. См. [workflow.py](backend/contexts/runs/application/workflow.py), [run.py](backend/interfaces/cli/run.py), [selfcheck.py](backend/interfaces/cli/selfcheck.py).
7. **Интерфейс.** React-консоль показывает поле, историю, решения, ранжирование, сравнение и ограничения; 11 экранов зарегистрированы в [pages.ts](frontend/src/app/router/pages.ts). Данные витрины лежат в [frontend/public/data](frontend/public/data); экран расчёта работает с API прогонов. Джарвис — отдельный сервис с инструментами по артефактам, документации и контексту экрана. Его подробная карта — [JARVIS_CONTEXT.md](JARVIS_CONTEXT.md). См. также [ARCHITECTURE.md](ARCHITECTURE.md) и [docker-compose.yml](docker-compose.yml).

Слои бэкенда: `shared`, 13 предметных контекстов с `domain/application/infrastructure`, внешние `interfaces/cli` и `interfaces/http`. Для технических вопросов есть [ARCHITECTURE.md](ARCHITECTURE.md) и [ARCHITECTURE_DIAGRAM.md](ARCHITECTURE_DIAGRAM.md). Старый контекст в `../aios-hack/context/` описывает структуру до рефакторинга (`backend/core`, `backend/ml` и другие старые пути); использовать его как исторический источник, а пути к коду проверять здесь.

## Границы утверждений для вопросов жюри

- Действующие траекторные веса обучены без рангового члена в loss. Ранговое качество измерено у бленда с отдельной экономической головой; исследовательские обучения с ранговым членом не являются production-весами. Источник: [SURROGATE_DEFENSE.md](../aios-hack/aios/SURROGATE_DEFENSE.md).
- Полный граф λ и обученный временной лаг в нейросеть не подаются. Политика пользуется λ, а суррогат получает агрегаты соседней закачки. Не называть рабочую модель графовой нейросетью. Источник: [SURROGATE_DEFENSE.md](../aios-hack/aios/SURROGATE_DEFENSE.md).
- OOD-фильтр отклоняет неподтверждённые режимы; он не делает прогноз на них точным. Исторические метрики не гарантируют перенос на новые ограничения или другое месторождение.
- Сравнение ЧДД планов корректно только при одинаковых условиях: кейс, период, дек, нормативы и методика. Именно для этого в прогоне и пакете сохранены хеши.
- В [competition-constraints.json](config/competition-constraints.json) нет годовых лимитов; 0.85–1.15 для компенсации имеет `compensation_enforcement=diagnostic`. Не выдавать его за блокирующее требование организаторов.
- Джарвис объясняет данные системы через инструменты и документы; он не управляет скважинами и не вычисляет заявляемый ЧДД. Без API-ключа текущий фронт показывает ошибку сервиса; автоматического воспроизведения фикстур в продукте нет.
